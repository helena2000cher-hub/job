# Деплой на VPS

Сайт работает в двух контейнерах:

- **app** — FastAPI отдаёт API и собранный фронтенд;
- **caddy** — принимает HTTPS-запросы и сам получает сертификат Let's Encrypt.

Данные (база, профиль, резюме) лежат на сервере в папке `data/` и не пропадают при обновлениях.

**Кто что видит:**

| Кто | Что видит |
|---|---|
| Гость (работодатель) | Демо на вымышленных данных: лента, разборы, трекер. Сбор вакансий и письма отключены |
| Владелец после входа по паролю | Свои данные и все функции |

## 1. Сервер

Подойдёт любой VPS с Ubuntu 22.04/24.04 и 1 ГБ RAM, например Timeweb Cloud или Selectel
за 300–500 ₽/мес. Если для бота уже есть VPS, можно использовать его же: нужны свободные порты 80 и 443.

Подключитесь к серверу и установите Docker:

```bash
ssh root@IP_СЕРВЕРА
curl -fsSL https://get.docker.com | sh
```

Заведите отдельного пользователя для деплоя:

```bash
adduser --disabled-password --gecos "" deploy
usermod -aG docker deploy
```

## 2. Домен

- **Свой домен:** создайте A-запись `job.ваш-домен.ru` → IP сервера.
- **Без домена:** используйте бесплатный `IP-через-дефисы.sslip.io`. Для IP `203.0.113.7`
  это `203-0-113-7.sslip.io`. Сертификат выпустится и для такого адреса.

## 3. Код и настройки

```bash
su - deploy
git clone https://github.com/helena2000cher-hub/job.git ~/job
cd ~/job
cp .env.example .env
nano .env
```

Что заполнить в `.env`:

| Переменная | Значение |
|---|---|
| `POLZA_API_KEY`, `EXA_API_KEY` | ключи, как локально |
| `APP_PASSWORD` | длинный пароль для входа |
| `SESSION_SECRET` | `python3 -c "import secrets; print(secrets.token_urlsafe(48))"` |
| `DOMAIN` | домен из шага 2 |

Чтобы `.env` не прочитали другие пользователи сервера:

```bash
chmod 600 .env
```

## 4. Перенос своих данных с компьютера

Выполните на своём компьютере, из папки проекта:

```bash
scp data/jobs.db data/profile.json data/resume.pdf deploy@IP_СЕРВЕРА:~/job/data/
```

## 5. Запуск

На сервере:

```bash
cd ~/job
sudo chown -R 1000:1000 data
docker compose up -d --build
docker compose logs -f app
```

Сайт откроется по адресу `https://ДОМЕН`. Без входа вы увидите демо. Чтобы попасть в свой кабинет,
нажмите значок входа справа вверху.

## 6. Автодеплой из GitHub

После каждого `git push` в `main` GitHub Actions прогоняет тесты, а если они зелёные — обновляет сервер.

1. На своём компьютере создайте отдельный ключ для деплоя:
   ```bash
   ssh-keygen -t ed25519 -f deploy_key -N ""
   ```
2. Добавьте публичную часть на сервер. Для этого выполните на сервере под пользователем `deploy`:
   ```bash
   mkdir -p ~/.ssh
   cat >> ~/.ssh/authorized_keys   # вставьте содержимое deploy_key.pub, затем Ctrl+D
   ```
3. В репозитории откройте **Settings → Secrets and variables → Actions** и добавьте секреты:
   - `VPS_HOST` — IP сервера;
   - `VPS_USER` — `deploy`;
   - `VPS_SSH_KEY` — содержимое файла `deploy_key` (приватная часть).
4. Удалите `deploy_key` с компьютера или уберите его в надёжное место.

Пока секреты не заданы, шаг деплоя в CI просто пропускается.

## Обслуживание

| Задача | Команда (на сервере, в `~/job`) |
|---|---|
| Логи | `docker compose logs -f app` |
| Перезапуск | `docker compose restart app` |
| Резервная копия базы | `cp data/jobs.db data/jobs-$(date +%F).db` |
| Сменить пароль | поправить `APP_PASSWORD` в `.env`, затем `docker compose up -d` (все старые входы сбросятся) |
