# Job Matcher — план проекта

> Личный сервис, который собирает вакансии из разных источников, сравнивает их с моим профилем
> (навыки, опыт, зарплата, формат, город) и показывает, что подходит, с объяснением *почему*.
> Публичный репозиторий служит ещё и портфолио.

Дата исследования: 15.10.2026

где каждый источник подключается отдельно, а данные приводятся к единой модели вакансии.

### 1.2 Подойдёт ли Exa.ai

**Что это.** Поисковик для AI-приложений. У него свой индекс на эмбеддингах, а не перепродажа
выдачи Google или Bing. Ищет по смыслу, а не по ключевым словам.

**Чем уникален:**
- **Смысловой запрос.** Можно спросить: «вакансии аналитика данных на удалёнке в небольших
  продуктовых компаниях» — и он найдёт страницы без точного совпадения слов.
- **Сразу отдаёт чистый текст страницы**, без HTML. Удобно передавать в LLM.
- **Find similar:** по ссылке на понравившуюся вакансию находит похожие.
- **Websets:** собирает списки сущностей по критериям (например, «компании, которые нанимают X»).
- Есть официальные SDK для Python и JS, а также MCP-сервер.

**Цена (exa.ai/pricing, октябрь 2026):** каждый месяц бесплатно $10 кредитов, баланс сбрасывается
1-го числа. Карта не нужна. Instant-поиск стоит $4 за 1000 запросов, Fast/Auto — $7 за 1000.
Для личного проекта этого хватает: около 1400–2500 запросов в месяц.

**Подходит ли для российского поиска — частично:**
- ✅ Понимает русский язык. С ноября 2025 Exa определяет язык запроса и по умолчанию
  возвращает страницы на том же языке.
- ❓ Насколько полно проиндексирован Рунет, публично не известно. Это придётся проверить своими запросами.
- ❌ hh.ru и другие крупные агрегаторы защищаются от ботов. Полных и свежих карточек
  оттуда через Exa, скорее всего, не будет.
- ❌ Пополнить баланс российской картой, скорее всего, не получится. Остаётся бесплатный лимит.

**Решение:** Exa используем как **дополнительный модуль «Разведка»**: поиск карьерных страниц
компаний, нишевых сайтов и «похожих вакансий». Основным источником он не будет.
Как альтернативу для Рунета стоит проверить Yandex Search API (Yandex Cloud).
Модуль поиска сделаем сменным.

### 1.3 Как устроены похожие продукты

Обычно в них три слоя: **агрегация → матчинг → трекинг откликов**. Лучшие решения
(Jobright, Teal, Huntr) делают акцент на трёх вещах:
1. **Оценка совпадения с объяснением.** Не просто «87%», а «совпало: SQL, Excel; не хватает: Python».
2. **Анализ пробелов**: каких навыков не хватает и насколько часто они встречаются в вакансиях.
3. **Трекер откликов** в виде канбана: «Интересно → Откликнулась → Собеседование → Оффер / Отказ».

## 2. Что входит в проект (ключевые аспекты)

1. **Профиль кандидата.** Загружаю резюме (PDF/DOCX/текст), LLM извлекает навыки, опыт, роли
   и отрасли. Потом я правлю результат вручную. Отдельно задаю потребности: город или удалёнка,
   минимальная зарплата, график, тип занятости, «стоп-слова» (например, «склад», «холодные звонки»).
2. **Сбор вакансий.** Коллекторы по источникам, единая схема, удаление дублей
   (одна вакансия на нескольких сайтах), обновление по кнопке и по расписанию.
3. **Матчинг в два этапа:**
   - *Жёсткие фильтры* (дёшево): город, формат, зарплата, стоп-слова.
   - *Смысловое сходство* (эмбеддинги): быстро отсеиваем нерелевантное.
   - *LLM-оценка* для топ-N: балл 0–100, что совпало, чего не хватает, «красные флаги»
     (например, «зарплата не указана», «по описанию похоже на продажи»).
4. **Интерфейс:** лента, карточка вакансии, трекер.
5. **Помощник отклика:** сопроводительное письмо под конкретную вакансию по моему профилю.
6. **Аналитика:** какие навыки чаще всего требуют в подходящих мне вакансиях и чего мне не хватает.
7. **Приватность:** резюме и ключи хранятся только локально (`.env`, `data/` в `.gitignore`).
   Репозиторий публичный, мои данные — нет.

## 3. Интерфейс: просто и понятно

Принцип: **один главный экран, три вкладки.** Никаких сложных настроек на старте.

```
┌──────────────────────────────────────────────────────────────┐
│  Job Matcher        [Лента]  [Трекер]  [Профиль]   ⟳ Обновить │
├───────────────┬──────────────────────────────────────────────┤
│ Фильтры       │  ● 92  Аналитик данных · ООО «Ромашка»        │
│ □ Удалёнка    │       Москва / удалёнка · 120–150 тыс.         │
│ Зарплата от   │       ✓ SQL ✓ Excel ✓ отчётность  ✗ Python     │
│ [ 80 000 ]    │       [★ Сохранить] [Скрыть] [Открыть →]       │
│ Источник      │  ─────────────────────────────────────────── │
│ ☑ Работа Рос. │  ● 81  Офис-менеджер · ...                     │
│ ☑ Telegram    │       ...                                      │
│ ☑ Вручную     │                                                │
│ Мин. балл: 60 │  [+ Добавить вакансию по ссылке]               │
└───────────────┴──────────────────────────────────────────────┘
```

- **Лента.** Карточки отсортированы по баллу. Цвет балла: зелёный ≥80, жёлтый 60–79.
  Совпавшие навыки отмечены ✓, недостающие ✗. Действия в один клик.
- **Карточка вакансии.** Полное описание, разбор от LLM («почему подходит»), кнопка
  «Написать сопроводительное», ссылка на оригинал.
- **Трекер.** Канбан с перетаскиванием и заметками (дата отклика, контакт, этап).
- **Профиль.** Навыки в виде тегов (можно добавлять и удалять), потребности, загрузка резюме.
- Тёмная и светлая тема, адаптивность под телефон, русский язык интерфейса.

## 4. Технологии (рекомендация)

| Слой | Выбор | Почему |
|---|---|---|
| Backend | **Python 3.12 + FastAPI** | Лучшая экосистема для парсинга, LLM и данных; хорошо смотрится в портфолио |
| БД | **SQLite** (через SQLModel), позже можно Postgres | Ничего не нужно устанавливать, один файл |
| Поиск по смыслу | Эмбеддинги + `sqlite-vec` | Векторный поиск прямо в SQLite |
| LLM | **polza.ai** (OpenAI-совместимый): Claude / DeepSeek / Qwen | Оплата из РФ, одна точка для всех моделей |
| Эмбеддинги | polza.ai: `baai/bge-m3` или `multilingual-e5-large` | Хорошо работают с русским |
| Внешний поиск | Exa (модуль «Разведка»), опционально Yandex Search API | См. 1.2 |
| Frontend | **React + Vite + TypeScript + Tailwind + shadcn/ui** | Современный стек, который ценят работодатели |
| Планировщик | APScheduler (обновление раз в N часов) | Просто, внутри backend |
| Качество | pytest, ruff, GitHub Actions (CI) | Показывает инженерную культуру |
| Запуск | Локально — два процесса (backend + frontend); на сервере — Docker Compose | Docker локально не установлен |

### polza.ai — что проверено
- Base URL `https://polza.ai/api/v1/`. Используем обычный SDK `openai` с этим адресом.
- В каталоге 313 чат-моделей, в том числе `anthropic/claude-sonnet-5.5`, `anthropic/claude-haiku-5.5`,
  `deepseek/deepseek-v4.1-flash` и `qwen/qwen3.8-flash`.
- 27 моделей эмбеддингов. Для русского текста подходят `baai/bge-m3`,
  `intfloat/multilingual-e5-large` и `qwen/qwen3-embedding-4b`.
- Нюанс: в `/embeddings` передавать **строки**, а не токены.
- Распределение моделей по задачам ради экономии:
  - Дешёвая быстрая модель (Haiku или DeepSeek Flash) — массовая оценка вакансий.
  - Сильная модель (Sonnet) — разбор резюме и сопроводительные письма.
  - Названия моделей хранятся в `.env`, их можно менять без правки кода.

### Удалёнка и источники — важная находка
В «Работе России» удалёнка указана в поле `employment` («Дистанционная (удаленная) работа»),
но фильтра по нему в API нет, и многие работодатели пишут об удалёнке только в тексте. Поэтому:
- признак «удалёнка» = поле `employment` **или** явная фраза в тексте (`collectors/remote.py`),
  в сомнительных случаях позже будем спрашивать LLM;
- запрос по всей России медленный (~15 с на страницу, удалённых ~1%), поэтому для удалёнки
  добавляем к запросу слова «удаленная» / «дистанционная»: выдача сужается с 8262 до ~100;
- удалённых офисных и IT-вакансий в trudvsem мало. Для удалёнки важнее другие источники:
  Telegram-каналы с удалёнкой, Хабр Карьера, GetMatch, карьерные страницы компаний (через Exa).
  Их стоит подключить раньше, сразу после MVP.
